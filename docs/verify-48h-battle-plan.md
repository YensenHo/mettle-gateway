## 二、跑探针（我做，拿 key 后立即执行）

```bash
cd ~/agent-pay-gateway/verify
python3 verify_probe.py \
  --base-url <base_url> \
  --api-key <key> \
  --model <model> \
  --ratio 1.0 \
  --before <充值后余额> --after <调用后余额>
```

**判定**：实际扣费 / 合理扣费（官方价×宣称倍率×汇率）> 1.5 → 倍率虚标。

## 三、发帖话术（定稿，发 LinuxDo + relayAPI issue 搭车）

> **标题**：做了个中转站余额真实性探针（对照法），实测 N 家，X 家倍率虚标
>
> **正文**：
> 用官方价 × 宣称倍率算「合理扣费」，再和前后余额差比对。实测 [家数] 家，[X] 家宣称 1.0 倍实际扣到 [Y] 倍。
> 想验自己 key 的，把 base_url + 前后余额截图发我，免费帮验一次（不看不存 key，只算差额）。

**设计逻辑**：①只给结果+免费帮验，不卖不问意愿；②「免费帮验一次」是钩子，换来的「私信求验」才是硬信号；③贴「N 家 X 家有问题」制造信息差逼出真实需求。

## 四、测供给侧（私信中转站，话术）

> 我做了个「余额真实性验证」工具，能帮你家站出「通过验证」的认证标识，证明你不虚标倍率。¥[X]/月 买认证标识，愿意吗？

**依据**：CCTest Partner ¥500/月、veridrop 认证收录已验证有人买（供给侧付费往往比买家侧更快更强）。

## 五、Go/No-Go 判定（48h 到点看数字）

- **硬 GO**：主动求验 ≥5 人，**或** ≥1 家中转站愿意付费 → 进红黑榜/Web 工具
- **软 GO（警惕）**：有人求验但都拒绝给 key → 「不存 key」没传达到位，补话术
- **NO-GO**：0 求验、0 问价、0 付费，只有点赞/顶帖 → 伪需求，砍（别把点赞当用户）
